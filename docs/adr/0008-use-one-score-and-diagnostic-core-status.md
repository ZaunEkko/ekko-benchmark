# ADR-0008：使用唯一分数和非计分核心诊断

## 状态

已接受。

## 背景

ADR-0006 使用 `69.9` 和 `89.9` 硬封顶，原意是防止辅助规则掩盖主流程缺口。校准时发现，大量能力差异明显的项目会聚集在两个上限值，分数失去区分度；报告同时出现原始分、最终分和等级，也让用户难以判断哪个数字才是实际评价。

等级本应只是分数区间的标签。如果先根据核心状态限制分数，再由分数生成等级，实际上是让等级设计反向参与计分，并对核心规则造成规则权重和封顶两次影响。

## 决策

- 只保留一个 `score`：先以 `pass=1`、`partial=0.5`、`fail=0` 计算维度分，再按画像维度权重合成；
- `unknown`、`not_applicable` 和 `waived` 不进入分母，保持原有语义；
- S/A/B/C/D/E/F 只按 `score` 所在区间映射，不封顶、不乘系数、不反向改分；
- 17 条核心软件交付规则继续存在，但只生成 `core.status` 和 `core.nonPassingRules` 诊断；
- 核心规则的状态已经参与普通加权，不再施加第二次惩罚；
- 静态和 Agent 语义评分都使用同一公式，并分别保留各自的核心诊断。

## 影响

- 不同高分项目不再集中显示为 `69.9` 或 `89.9`；
- 某个项目即使核心诊断为 `blocked`，等级仍严格由分数决定，报告会并列提示风险；
- 首次公开发布前移除 JSON 报告中的 `weightedScore`、`gate` 和 `scoreCap`，改为单一 `score` 与非计分 `core`；
- ADR-0006 的封顶决策和 ADR-0007 的核心通过条件被本决策取代，原有等级区间与维度权重继续有效。
