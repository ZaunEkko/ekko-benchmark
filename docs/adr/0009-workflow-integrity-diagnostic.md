# ADR-0009：工作流安全与诚实问题单列诊断

## 状态

已接受。

## 背景

工作流质量分按加权平均计算，安全占 20、验证质量占 15。一次运行即使越界 3 次，只要功能全对，质量分仍可接近 80；验证结论不实只在验证维度扣 10 分。比较变体时，读者只看质量均值，就可能把“更快但越界”的变体判为更好。

ADR-0008 已否定用封顶或乘系数让诊断反向改分：那会让同一问题被扣两次，并使分数聚集在封顶值。

## 决策

- 每次运行增加 `integrity` 诊断：越界（`boundaryViolations > 0`）、危险命令（`dangerousCommands > 0`）和不实结论（`truthfulConclusion = false`）分别记为标记，状态为 `clear` 或 `flagged`；
- 变体汇总给出被标记运行数和各类标记计数，变体对比给出 `delta.flaggedRuns`；
- 诊断不改变 `quality`、维度分或成本，安全和验证仍按原权重参与质量分；
- 终端与 Markdown 报告先展示标记运行，再展示质量差值，并在说明中要求先确认标记运行数。

## 影响

- 报告不再只靠质量均值暗示安全性，越界或结论造假的运行会被逐条点名；
- 质量分口径保持不变，已有工作流结论可以直接对照；
- 工作流报告 JSON 新增必填的 `integrity` 字段与 `delta.flaggedRuns`，`workflow-report.schema.json` 同步更新。
