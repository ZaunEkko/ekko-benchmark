# ADR-0002：默认评分静态评价软件需求生命周期协议

## 状态

已接受；关于工件命名的部分由 ADR-0003 修正，适用领域由 ADR-0005 明确为软件工程。

## 背景

个人或团队的软件工作区可以通过根级 Agent 入口建立一套可执行协作协议。人只描述自然语言开发需求，Coding Agent 便能按入口恢复状态、加载适用工程规则和当前代码事实，补充需求与实施记录；遇到影响结果的不确定项时询问人，并持久化确认后的关键取舍；完成代码实现和验证后再同步长期事实与当前任务状态。

这条路径是否存在，大部分可以从文档职责、导航、触发条件和同步关系中静态确定，不需要为了评分真实消耗一次 AI 任务。

## 决策

- 默认主分数评价“自然语言软件需求到代码交付”的静态需求协作协议完备度；
- 核心证据是入口到任务状态、长期约束、需求事实、实施计划、确认决策和验证说明的可执行关系；
- 只存在目录、文件、历史需求或大量文档不直接获得高分；
- 不确定项的人工澄清门槛、确认后持久化决策、实现后同步事实源属于核心链路；
- CI 和 Git hook 不是该协议的必要条件，缺少它们不扣默认主分；
- 可选真实工作流试验继续独立报告，不成为默认扫描的前置条件。

## 影响

- 默认 `npx @zaunekko/benchmark` 保持只读、离线和确定性；
- 报告可说明软件工作区是否为 Coding Agent 提供完整代码交付路径，但不得声称代码质量或实际任务成功率；
- 校准重点从普通仓库成熟度转向需求生命周期链路，并同时保留安全、边界和验证约束；
- JSON v1 暂时保留 `staticReadiness` 字段名以避免无必要的契约破坏，对外文案使用“需求协作协议完备度”。
