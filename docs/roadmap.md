# 项目路线与当前状态

> 当前阶段：`0.1.0` 软件工程静态需求协作协议本地发布候选，尚未提交或发布。

实现语言为 TypeScript；仓库不提交生成的 JavaScript，发布包由 `prepack` 编译到 `dist/`。

产品范围固定为软件工程中的 Coding Agent 协作。通用能力只在其服务于自然语言软件需求到代码交付时评价，不扩展小说、视频、研究、设计或办公等非软件工程领域。

## 已完成

- 确立默认静态协议完备度与可选真实工作流效果分离的两层模型；
- 提供零参数当前目录扫描、画像自动识别、证据定位和终端/JSON/Markdown 报告；
- 提供中文宽字符对齐的终端总览、证据化问题清单、确定性短评和 Coding Agent 语义复核接力；
- 将默认主分数改为“自然语言软件需求到代码交付”的静态协作协议完备度，不要求真实跑任务；
- 覆盖开发需求接入、工程上下文路由、需求与计划关联、人工澄清、决策持久化、代码实施、验证和状态同步链路；
- 评分规则基于抽象协作能力，已用 `Spec/Design/ADR/HANDOFF` 风格、OpenSpec 风格和无约定命名的自定义风格做等价性回归；
- 移除“必须存在 CI 或 hook”的默认扣分，避免把普通仓库成熟度当成 Agent 协作能力；
- 提供 `personal-local-multirepo` 与 `team-shared-repo` 两种画像；
- 提供显式配置、分数门禁和理由必填的 waiver；
- 提供真实工作流试验记录的校验、评分、变体汇总和成本差值；
- 固定配置、工作流输入、静态报告和工作流报告的 JSON Schema；
- 使用多个 Java、Python、Godot/.NET 和插件软件工作区做只读误报校准，不把其人工分作为标准答案；
- 完成符号链接、越界链接、超大入口、非 UTF-8、跨栈识别和干净 tarball 安装验证；
- 建立 TypeScript 严格检查、跨平台测试、构建与发布前统一门禁。
- 评分收敛为唯一加权 `score`，核心软件交付规则单列诊断但不封顶或二次扣分；
- 增加 95-100 的 S 级，并让所有等级只由分数区间决定；
- 提高验证与安全权重，并为画像权重记录明确的软件交付依据；
- 收紧主动澄清、完整上下文、验证结果协议和接续状态证据，补充对应反例测试；
- 完成两个真实工作区样本的静态/Agent 双层校准，结果与未检查范围见 [`calibration/2026-09-03-two-samples.md`](calibration/2026-09-03-two-samples.md)；
- 扩展裸 Markdown 路径、子仓库相对路径、分步开工流程、局部规则加载和 npm 静态检查脚本识别；
- 扫描前遵守根入口明确声明的目录读取禁令，并在报告中披露排除范围；
- 完成 `0.1.0` tarball 清单复核和隔离安装验收，安装后的 `npx` 扫描与 `agent` 协议可运行；
- 规则同时识别中文与英文协作文档，逐句对译样本的逐条判定一致，并以 5 个真实工作区确认中文判定无回退；
- CI 已配置 Linux 与 Windows 上的 Node.js 22/24 矩阵、完整验证和发布包 dry-run。

## 发布前必须完成

- 首次提交后在远程 CI 实际执行 Linux 与 Windows 上的 Node.js 22/24、权限受限目录回归和包清单检查；
- 复核包名、版本和发布清单后，再单独讨论 npm 发布。

## 后续阶段

1. 增加可选 HTML 报告和 SARIF 输出；
2. 扩展更多需求文档体系和 Agent 入口格式的确定性识别；
3. 基于已实现的 `improvements` 改进计划与 Agent 改进阶段，补充按项目结构生成的协议草稿模板；
4. 扩展 `oss-agent-ready` 与 `enterprise-controlled` 画像；
5. 可选工作流试验评分器独立演进，不作为默认扫描前置条件。

## 明确不做

- 不根据静态分数预测真实任务成功率；
- 不评价非软件工程领域的通用人机协作能力；
- 不把代码质量、框架选择或项目规模直接换算为协作协议分；
- 不要求用户真实运行一次 AI 任务才能获得默认分数；
- 不在静态扫描路径调用模型或访问网络；
- 不把文档数量、历史需求数量或 CI 存在性直接当成协作闭环；
- 不自动执行被测仓库中的构建、数据库、发布或修复命令；
- 不为了让某个样本得高分而修改规则。
